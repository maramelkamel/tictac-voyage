EXPLICATION PRINCIPALE DU CODE PAGE PAR PAGE - TICTAC VOYAGE

OBJECTIF DU FICHIER

Ce document explique, pour chaque page principale du projet, les parties de code a lire en priorite et ce que chaque partie fait exactement.

Mode de lecture conseille :
1. regarder la route dans `frontend/src/App.jsx`
2. ouvrir le fichier de page correspondant
3. lire dans cet ordre :
   - imports
   - hooks d'etat
   - hooks de chargement (`useEffect`, `useMemo`)
   - handlers (clic, recherche, submit, navigation)
   - JSX rendu
   - appels API relies


1. ROUTAGE PRINCIPAL

Fichier central :
- `frontend/src/App.jsx`

Ce fichier fait exactement :
- importe toutes les pages principales
- initialise `BrowserRouter`
- mappe chaque URL a un composant React
- separe les modules publics, client et admin

C'est le point de depart pour comprendre :
- quelle page s'ouvre pour quelle URL
- quelles pages forment un tunnel complet : liste -> detail -> reservation -> paiement


2. STRUCTURE COMMUNE D'UNE PAGE REACT DANS LE PROJET

La plupart des pages suivent cette structure :

1. `imports`
- import React, hooks et router
- import des composants partages : `Navbar`, `Footer`, cartes, formulaires, sections promo
- import des styles CSS
- import des hooks maison : promotions, favoris, langue

2. `state`
- stocke les champs de formulaire 
- stocke les donnees chargees depuis l'API
- stocke `loading`, `error`, `submitted`, `selected`, `filter`

3. `useEffect`
- charge les donnees au montage
- recharge si un filtre ou un id change
- synchronise certains champs derives

4. `handlers`
- `handleSearch`
- `handleChange`
- `handleSubmit`
- `handleDetails`
- `handleReserve`
- `handleFavoriteToggle`
- `navigate(...)` pour passer d'une page a l'autre

5. `render JSX`
- hero / bandeau principal
- filtres et formulaires
- cartes listees
- resume lateral
- boutons d'action

19. LECTURE RAPIDE PAR TYPE DE PAGE

Pour une page catalogue :
- lire `useEffect()` de chargement
- lire `useMemo()` de filtrage
- lire `handleDetails()` et `handleReserve()`

Pour une page detail :
- lire `useLocation()` / `useParams()`
- lire le bloc de chargement API
- lire le bouton reserver

Pour une page reservation :
- lire `form`
- lire `handleChange()`
- lire le calcul total
- lire `handleSubmit()`

Pour une page paiement :
- lire `saveReservation()` ou `bookFlight()`
- lire le payload final
- lire la distinction `online` / `agency`

Pour une page admin :
- lire `fetch...()`
- lire les etats de filtres
- lire les endpoints `PATCH`, `PUT`, `DELETE`
- lire la logique de modale/detail


20. RESUME FINAL

Si vous voulez comprendre "ce que chaque partie du code fait exactement", retenez cette logique globale :

- `App.jsx` decide quelle page s'ouvre
- les pages catalogue chargent les donnees et filtrent
- les pages detail affichent une offre choisie
- les pages reservation collectent les informations utilisateur
- les pages paiement envoient la reservation finale au backend
- `ClientProfile.jsx` rassemble toutes les donnees du client
- les pages admin font du CRUD, du suivi et du changement de statut

Le coeur du projet est donc :
- navigation React Router
- gestion d'etat avec `useState`
- chargement donnees avec `useEffect`
- optimisation de listes avec `useMemo`
- communication backend avec `fetch(...)`
- transmission d'etat entre pages avec `navigate(..., { state })`
