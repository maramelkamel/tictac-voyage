VOYAGE ORGANISE EXPLICATION

1. OBJECTIF DU MODULE

Le module "voyage organise" permet a un visiteur ou a un client connecte :
- de consulter la liste des voyages organises disponibles
- de filtrer et trier les voyages
- d'ouvrir la page detail d'un voyage
- de remplir un formulaire de reservation
- de choisir un mode de paiement
- d'enregistrer la reservation dans la base de donnees

Ce module est separe en deux grandes parties :
- frontend : affichage, navigation, experience utilisateur
- backend : routes API, validation, acces base de donnees, suivi des reservations


2. OUTILS ET PACKAGES UTILISES

FRONTEND
- React : construit les pages et les composants du module
- react-router-dom : permet la navigation entre liste, detail, reservation et paiement
- fetch : envoie les requetes HTTP vers le backend
- localStorage : recupere les informations du client connecte pour pre-remplir le formulaire

BACKEND
- Node.js : environnement d'execution du serveur
- Express : expose les routes API du module
- pg / PostgreSQL : execute les requetes SQL et stocke les voyages + reservations
- Nodemailer : envoie les emails quand le statut d'une reservation change

4. PROCESSUS COMPLET DE 0 A LA FIN

ETAPE 1 : AFFICHAGE DE LA LISTE DES VOYAGES

Fichier principal :
- frontend/src/pages/VoyagesOrganise/VoyagesOrganise.jsx

Ce que fait la page :
- au chargement, elle appelle l'API publique :
  GET /api/voyages-organises?public=true
- elle recupere la liste des voyages actifs depuis la base
- elle normalise les donnees pour les adapter au composant VoyageCard
- elle affiche les promotions, les filtres, le tri et les cartes

Important :
- les filtres de recherche sont geres cote frontend apres chargement de la liste
- useMemo est utilise pour recalculer la liste finale affichee


ETAPE 2 : OUVERTURE DE LA PAGE DETAIL

Fichier :
- frontend/src/pages/VoyagesOrganise/Detail.jsx

Quand l'utilisateur clique sur "details" :
- la page liste utilise navigate()
- l'objet voyage est passe dans state via react-router-dom

La page detail :
- lit state.voyage
- affiche les informations principales
- construit une galerie
- affiche le programme, les inclus, les non inclus et le bloc prix

Pourquoi cette approche :
- elle evite un nouvel appel API juste pour afficher le detail
- elle garde une navigation fluide


ETAPE 3 : FORMULAIRE DE RESERVATION

Fichier :
- frontend/src/pages/VoyagesOrganise/Reserver.jsx

Role :
- collecter les informations du client
- pre-remplir nom, prenom, email, telephone si le client est connecte
- calculer un total estime selon le nombre de voyageurs
- transmettre les informations a la page paiement

Important :
- a cette etape, aucune reservation n'est encore ecrite en base
- les donnees sont seulement preparees cote frontend

Donnees collectees :
- prenom
- nom
- email
- telephone
- nombre de voyageurs
- type de chambre
- notes


ETAPE 4 : CHOIX DU PAIEMENT ET ENREGISTREMENT FINAL

Fichier :
- frontend/src/pages/VoyagesOrganise/Payment.jsx

Cette page recoit :
- le voyage choisi
- les informations du formulaire
- le prix total estime

Deux cas metier existent :

1. Paiement en ligne
- l'utilisateur remplit une interface de carte
- la page appelle saveReservation("online")
- une requete POST est envoyee a :
  /api/voyage-reservations

2. Paiement a l'agence
- l'utilisateur confirme qu'il paiera plus tard en agence
- la page appelle saveReservation("agency")
- une requete POST est envoyee au meme endpoint

Important :
- dans les deux cas, la reservation est enregistree en base
- le vrai mode de paiement choisi est stocke dans payment_method

11. RESUME

Le module "voyage organise" suit une architecture classique mais propre :
- frontend pour l'affichage et la navigation
- backend pour la logique metier et la persistence
- base de donnees pour stocker les voyages et les reservations

Le frontend gere l'experience utilisateur de bout en bout, tandis que le backend assure :
- la validation
- l'enregistrement
- la mise a jour des statuts
- la communication avec la base

Ainsi, le module permet de passer d'une simple consultation de voyages a une reservation complete et traçable.


Le module VoyagesOrganise suit ce parcours :

VoyagesOrganise.jsx
Affiche la liste des voyages organisés

Detail.jsx
Affiche le détail d’un voyage

Reserver.jsx
Récupère les informations du client

Payment.jsx
Finalise la réservation et l’enregistre dans la base

backend/routes + controllers + models
Gèrent les API et l’accès PostgreSQL

1. Frontend : liste des voyages
Fichier :
VoyagesOrganise.jsx

Fonctions importantes :

normalize(v)
Rôle :
transforme une ligne brute venant du backend en objet exploitable par l’interface.

Exemple :

title devient titre
image_url devient image
price devient prix
available_spots devient places
Pourquoi c’est utile :
le backend renvoie une structure base de données, alors que les composants frontend ont besoin d’une structure plus simple et plus lisible.

useEffect(() => { fetchVoyages() }, [])
Rôle :
charge les voyages au démarrage de la page.

Ce qu’il fait :

appelle GET /api/voyages-organises?public=true
récupère j.data
applique normalize sur chaque voyage
stocke le résultat dans voyages
clearFilters()
Rôle :
remet à zéro les filtres avancés.

clearSearch()
Rôle :
vide les champs de recherche :

destination
date
personnes
durée
useMemo(...) avec displayed
Rôle :
calcule la liste finale affichée.

Il applique :

filtre destination
filtre nombre de personnes
filtre durée
filtre date de départ
filtre catégorie
filtres avancés
tri final
Pourquoi useMemo :
pour éviter de recalculer toute la liste à chaque rendu si rien n’a changé.

handleDetails(voyage)
Rôle :
ouvre la page détail du voyage.

Navigation :
/VoyagesOrganise/Detail/:id

handleReserver(voyage)
Rôle :
envoie l’utilisateur vers la réservation directe.

2. Frontend : détail d’un voyage

Detail.jsx

Fonctions importantes :

buildGallery(mainImage, destination)
Rôle :

Ce qu’elle fait :

handleReserver()
Rôle :

prevPhoto() et nextPhoto()

4. Frontend : paiement et enregistrement
Fichier :
Payment.jsx

C’est la page la plus importante du flux métier.

Variables importantes :

method
contient le mode de paiement :

online
agency
cardType
type de carte choisi

cardForm
contient les champs carte :

numéro
nom
expiration
cvv
adresse
submitted
indique si la réservation a réussi

apiError
contient l’erreur backend si l’API échoue

Fonctions importantes :

saveReservation(paymentMethod)
Rôle :
c’est la fonction clé du module côté frontend.

Ce qu’elle fait :

construit payload
envoie un POST à :
http://localhost:5000/api/voyage-reservations
vérifie json.success
retourne la réservation créée
Données envoyées :

voyage_id
first_name
last_name
email
phone
chambre_type
number_of_persons
total_price
payment_method
notes
handleCardChange(e)
Rôle :
formate les champs carte côté interface.

Exemple :

ajoute des espaces au numéro
transforme MMYY en MM/YY
limite le cvv
Important :
c’est de la mise en forme UI, pas un vrai paiement bancaire réel.

handleOnlineSubmit(e)
Rôle :
confirme une réservation avec paiement en ligne.

Ce qu’elle fait :

appelle saveReservation('online')
si succès : submitted = true
sinon : affiche l’erreur
handleAgencyConfirm()
Rôle :
confirme une réservation avec paiement à l’agence.

Ce qu’elle fait :

appelle saveReservation('agency')
si succès : écran de confirmation
Important :

dans les deux cas, la réservation est enregistrée en base
seul payment_method change
