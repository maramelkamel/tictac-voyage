DESCRIPTION COMPLETE DU PROJET TICTAC VOYAGE

1. VUE D'ENSEMBLE

Tictac Voyage est une plateforme web de voyage composee de :
- un frontend React/Vite pour les clients et les administrateurs
- un backend Node.js/Express expose via des routes API REST
- une base PostgreSQL pour les clients, offres, reservations, favoris, promotions et messages
- un systeme d'emails transactionnels pour bienvenue, confirmation, suivi et reinitialisation du mot de passe

Le projet couvre les modules suivants :
- Hotels
- Vols / billeterie
- Omra
- Voyages organises
- Circuits
- Transport
- Voyage sur mesure
- Contact
- Favoris
- Compte client
- Administration

Page d'accueil actuelle :
- `/` et `/hotels` pointent vers le module Hotels


2. ARCHITECTURE GENERALE

Frontend :
- `frontend/src/App.jsx` contient le routage principal
- `frontend/src/pages` contient les pages publiques, client et admin
- `frontend/src/components` contient les composants reutilisables
- `frontend/src/hooks` contient la logique partagee (promotions, favoris, langue)
- `frontend/src/i18n` gere le multilingue FR / EN / AR

Backend :
- `backend/Server.js` charge toutes les routes API
- `backend/routes` declare les endpoints
- `backend/controllers` gere la logique metier
- `backend/models` dialogue avec la base
- `backend/services` gere les integrations externes
- `backend/utils/mailer.js` centralise les emails

3. PAGES PUBLIQUES ET LEUR ROLE

3.1 Authentification client

`/CreateAccount`
- page de creation de compte client
- formulaire complet : prenom, nom, email, telephone, mot de passe, confirmation, situation matrimoniale, nombre d'enfants, ville
- validation frontend
- envoi a `POST /api/auth/register`
- en cas de succes : sauvegarde du token et du client dans le stockage local

`/SignIn`
- page de connexion client
- email + mot de passe
- option "se souvenir de moi" cote interface
- envoi a `POST /api/auth/login`
- en cas de succes : stockage du token/client et redirection vers `/hotels`

`/ForgotPassword`
- premiere etape de mot de passe oublie
- saisie email
- envoi d'un code par email via `POST /api/auth/forgot-password`
- verification du code via `POST /api/auth/verify-reset-code`

`/ResetPassword`
- deuxieme etape de reinitialisation
- definie un nouveau mot de passe avec validation
- envoi a `POST /api/auth/reset-password`


3.2 Hotels

`/` et `/hotels`
- page catalogue hotels et page d'accueil actuelle
- hero dynamique avec images de couverture recuperees via API
- barre de recherche hotel
- promotions hotels
- filtres par ville, budget, vedettes, tri
- cartes hotels
- favoris pour utilisateur connecte
- section "coups de coeur" / hotels populaires

`/hotels/results`
- reutilise la meme page de catalogue avec les resultats

`/hotels/details/:id`
- fiche detaillee d'un hotel
- informations, galerie, tarifs, equipements, disponibilite
- point d'entree vers la reservation

`/hotels/reserve`
- formulaire de reservation hotel
- pre-remplissage si client connecte
- collecte :
  nom, prenom, email, telephone
  check-in, check-out, adultes, enfants, chambres
  type de chambre, formule repas, vue, preference de lit
  heure d'arrivee, transfert aeroport, extras, demandes speciales
- calcul local du total
- redirection vers la page de paiement hotel

`/hotels/payment`
- choix du mode de paiement :
  paiement en ligne
  paiement a l'agence
- enregistrement via backend
- gestion de confirmation et message final


3.3 Vols / Billeterie

`/flights`
- page principale de recherche de vols
- recherche aller simple ou aller-retour
- depart, arrivee, dates, adultes, enfants, classe cabine, vols directs
- recherche temps reel via `POST /api/flights/search`
- sections additionnelles :
  meilleures offres
  prochains departs
  arguments commerciaux
- promotions billeterie

`/flights/results`
- liste des offres retournees par l'API vols
- comparaison des itineraires, horaires, prix et compagnie

`/flights/details`
- fiche detail d'une offre choisie
- recap du trajet, segments, conditions et prix

`/flights/reserve`
- formulaire passager
- pre-remplissage si client connecte
- validation forte :
  identite comme sur passeport
  telephone normalise
  numero et expiration du passeport
  pays de delivrance
- redirection vers paiement

`/flights/payment`
- choix paiement en ligne ou agence
- enregistrement backend via `POST /api/flights/book`
- confirmation, statut paiement et notification

`/billeterie/Billeterie`
- ancienne entree/module billeterie encore route dans l'application
- coexiste avec le nouveau module `/flights`


3.4 Omra

`/Omra/Omra`
- liste des forfaits Omra publics
- hero dynamique
- promotions Omra
- filtres par type de forfait
- favoris
- contenu marketing : pourquoi nous choisir, CTA

`/Omra/Details/:id`

- programme, inclus, prix, photos, depart

`/Omra/Reserve/:id`
- formulaire de reservation Omra

- collecte :
  prenom, nom, telephone, email
  genre, passeport, type de chambre, nombre de personnes

`/Omra/OmraPayment/:id`

5. PROCESSUS METIER PRINCIPAUX

5.1 Processus d'inscription client

1. L'utilisateur ouvre `/CreateAccount`
2. Il remplit le formulaire
3. Le frontend valide
4. Le backend cree le client via `/api/auth/register`
5. Le mot de passe est chiffre
6. Le token JWT est renvoye
7. Le client est stocke en local
8. Un email de bienvenue peut etre envoye


5.2 Processus de connexion client

1. L'utilisateur ouvre `/SignIn`
2. Il saisit email et mot de passe
3. Le frontend appelle `/api/auth/login`
4. Le backend verifie le compte et renvoie un JWT
5. Le frontend stocke `token` et `client`
6. L'utilisateur est redirige vers l'accueil hotels


5.3 Processus mot de passe oublie

1. L'utilisateur saisit son email sur `/ForgotPassword`
2. Le backend genere un code
3. Le code est envoye par email
4. L'utilisateur saisit le code
5. Le backend verifie le code
6. L'utilisateur arrive sur `/ResetPassword`
7. Il definit son nouveau mot de passe
8. Le backend met a jour le mot de passe chiffre


5.4 Processus reservation standard (Omra, voyages, circuits)

1. Le client consulte une liste
2. Il ouvre une page detail
3. Il clique sur reserver
4. Il remplit le formulaire
5. Le total est calcule cote frontend
6. Il choisit un mode de paiement
7. La reservation est envoyee au backend
8. Le backend enregistre la reservation
9. Le statut paiement est renseigne
10. Une confirmation/message final est affiche
11. Un email peut etre envoye


5.5 Processus reservation hotel

1. Recherche hotel
2. Consultation fiche hotel
3. Saisie de la reservation complete
4. Choix de la formule repas et options
5. Calcul du nombre de nuits et du montant
6. Choix du mode de paiement
7. Envoi a `/api/hotels/book`
8. Enregistrement dans les reservations hotel
9. Confirmation utilisateur


5.6 Processus reservation vol

1. Recherche en temps reel via `/api/flights/search`
2. Choix d'une offre
3. Consultation detail offre
4. Saisie des informations passager exactes
5. Validation passeport/telephone
6. Choix du mode de paiement
7. Appel a `/api/flights/book`
8. Creation reservation + eventuelle interaction fournisseur vols
9. Retour de confirmation/statut


5.7 Processus transport

1. Choix du service : transfert ou mise a disposition
2. Saisie de l'itineraire
3. Saisie vehicule, passagers et options
4. Saisie coordonnees client
5. Envoi a `/api/requests`
6. L'admin traite la demande
7. Mise a jour du statut dans l'admin


5.8 Processus voyage sur mesure

1. Le client remplit la demande personnalisee
2. Le backend enregistre la demande dans `/api/custom-trips`
3. L'admin consulte la demande
4. L'admin ajoute un devis et un message
5. Le client retrouve l'offre dans son compte


5.9 Processus contact

1. Le client remplit le formulaire contact
2. Le backend enregistre la demande
3. L'admin consulte le message
4. L'admin met a jour le statut et peut ajouter une note/reponse
5. Le client peut retrouver un suivi dans son espace


5.10 Processus favoris

1. Le client connecte clique sur coeur/favori
2. Le frontend appelle `/api/favorites/toggle`
3. Le backend ajoute ou retire le favori
4. Les favoris sont visibles dans `/mon-compte`


5.11 Processus promotions

1. L'admin cree une promotion
2. La promotion est liee a une categorie
3. Les pages publiques concernes l'affichent automatiquement via hook
4. Le client retrouve aussi les promotions dans son compte
5. Un envoi de campagne email est possible cote admin


5.12 Processus administration des reservations

1. Les reservations arrivent dans le module admin correspondant
2. L'admin filtre/lit les demandes
3. L'admin change le statut : pending, confirmed, completed, cancelled selon le module
4. Les donnees sont mises a jour en base
5. Le dashboard global se met a jour

Le parcours principal du projet est :
- creer un compte ou se connecter
- consulter un catalogue
- appliquer des filtres
- ouvrir la fiche detail
- reserver
- choisir un paiement
- recevoir une confirmation

Le parcours administrateur est :
- se connecter a l'admin
- suivre les indicateurs dans le dashboard
- gerer les catalogues
- traiter les reservations et demandes
- publier des promotions
- gerer les clients et admins


11. RESUME COURT DU PROJET

Tictac Voyage est un systeme complet de gestion d'agence de voyage qui combine :
- un site public de vente et de demande de services
- un espace client avec historique, fidelite, favoris et promotions
- un back-office admin multi-modules
- des APIs metier specialisees par produit
- des processus de reservation coherents pour hotels, vols, Omra, circuits, voyages et transport

Le projet est donc a la fois :
- une vitrine commerciale
- un tunnel de reservation
- un CRM operationnel simplifie
- un outil de gestion interne d'agence
